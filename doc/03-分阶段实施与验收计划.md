# 03 · 分阶段实施与验收计划

## 1. 交付原则

先证明“输入可读、输出正确、失败可恢复”，再完善界面和发布。每阶段满足退出条件才进入下一阶段。以下工期是单名熟悉 Node/FFmpeg 的开发者集中投入的粗估，不是承诺；不包含桌面签名、多平台硬件适配和等待试用反馈。

| 阶段 | 优先级 | 预估投入 | 交付物 |
| --- | --- | --- | --- |
| M0 技术验证 | P0 | 1–2 人日 | 可复现的探测、转换和对照记录 |
| M1 转换核心 | P0 | 2–4 人日 | 参数构造、任务状态机、文件保护、自动测试 |
| M2 本地网页 MVP | P0 | 3–5 人日 | 导入、设置、队列、结果和安装流程 |
| M3 使用体验 | P1 | 2–4 人日 | 短片预览、诊断完善、可访问性、真实用户试用 |
| M4 开源发布 | P1 | 1–2 人日 | 双语文档、演示、CI、版本发布资料 |

合计约 9–17 人日；M0 若发现 HDR、编码质量或权限问题，应调整范围，不靠增加并发或隐藏错误赶进度。

## 2. M0：技术验证

### 工作清单

- [ ] 记录 OS、CPU/架构、内存、Node、FFmpeg 版本与构建信息。
- [ ] 检测 ffprobe、libx264、h264_videotoolbox，并用实际编码验证能力。
- [ ] 生成可再分发的彩条、色块、正弦音测试素材；真实手机素材只保存在本地。
- [ ] 对同一 SDR 样本分别软件和硬件编码，评估耗时、体积、视觉质量。
- [ ] 验证灰阶、音画同步、旋转、无音频和中文路径。
- [ ] 验证目录直读以及流式暂存，不依赖浏览器真实路径。
- [ ] 识别 HDR，并确认首版能够给出明确的不支持说明。

### 退出条件

本机至少一条编码路径稳定完成；导出可播放、声音策略正确、方向正确。给出实测记录和失败样本，不要求硬件路径必须胜出。速度优先预设质量不达标时，暂不开放该预设。

## 3. M1：转换核心

### 工作清单

- [ ] 建立 TypeScript 项目、锁文件、明确的运行时范围和模块边界。
- [ ] 实现能力探测、受限文件注册、ffprobe 解析和参数构造。
- [ ] 实现串行队列、队列暂停、取消、attempt 重试。
- [ ] 实现结构化进度、错误分类、原子快照与异常退出恢复。
- [ ] 实现输出唯一命名、临时文件、验证后提交和无覆盖行为。
- [ ] 实现本地鉴权、根目录限制和协议限制。

### 退出条件

无需 UI 即可完成一批混合素材转换；单个失败不会阻塞后续任务；取消后无残留运行进程；原文件和已有输出不被覆盖；重启不会把中断任务标记完成。

## 4. M2：本地网页 MVP

### 工作清单

- [ ] 一条启动命令开启服务并打开页面，端口冲突可恢复。
- [ ] 授权目录浏览、多选、拖拽暂存及其进度。
- [ ] 预设设置、提交前输出位置和不保留流提示。
- [ ] 队列进度、取消、重试、暂停后续队列。
- [ ] 刷新恢复、SSE 重连、未知时长展示。
- [ ] 结果播放、输出位置显示和文件管理器定位。
- [ ] 缺依赖、源丢失、权限不足、磁盘不足、损坏输入的友好错误。

### 退出条件

macOS 在依赖已安装的情况下，新用户可按 README 独立完成一次转换。安装后断网也能完成导入和转换；网页不加载外部字体、脚本或分析服务。连续 20 个混合任务执行完毕，所有失败均有解释及操作入口。

## 5. M3：让用户愿意长期使用

- [ ] 增加可选时间点的 3–5 秒真实短片预览，复用导出滤镜与编码配置。
- [ ] 展示源片/结果对比、实际编码器、体积变化和耗时。
- [ ] 增加历史结果和暂存清理入口，清楚标识删除范围。
- [ ] 保留设置偏好，改善键盘操作、焦点和错误提示。
- [ ] 让 3–5 名目标用户试用，记录卡点；不强制上传媒体和诊断信息。

退出条件：试用者能理解两种导入方式、找到结果、处理一次失败；高频卡点已修复。若安装依赖成为主要流失原因，优先评估桌面分发，再讨论增加滤镜。

## 6. M4：公开发布

- [ ] 中英文 README、许可证、贡献指南、Issue/PR 模板、变更记录。
- [ ] 20–40 秒录屏演示：导入 → 预览 → 批量进度 → 结果。
- [ ] 软件编码集成测试进入 CI；macOS 硬件测试与普通 CI 结果分开标注。
- [ ] 从干净目录按 README 完成安装和首次转换。
- [ ] 打版本标签前检查仓库不包含真实用户视频、绝对路径日志或构建缓存。
- [ ] 发布内容只描述已完成并验证的功能，支持矩阵显示未验证平台。

实际发布、推送或对外发帖属于后续执行事项；本文仅规划交付物，不表示已执行。

## 7. 验收矩阵

| 场景 | 必须满足的结果 | 阶段 |
| --- | --- | --- |
| SDR 彩条 + AAC | 输出有连续灰阶，音频策略正确，可播放 | M0/M1 |
| 无音轨、带封面、多个音轨 | 主视频选择正确，额外流说明准确 | M1 |
| 中文、空格、引号及 shell 字符文件名 | 正常处理，字符不能变成命令执行 | M1 |
| 重名、源输出同目录 | 原片及已有结果均未改写 | M1 |
| 超过 2 GB 输入 | 目录直读可运行；暂存不会整文件驻留内存 | M2 |
| 损坏视频夹在 20 个任务中 | 当前失败可解释，其余继续 | M2 |
| 探测中/编码中/验证中取消 | 结果状态一致，子进程退出，原片保留 | M1/M2 |
| 服务崩溃、重启、浏览器刷新 | 无假完成，队列可恢复，无自动断点续转宣传 | M2 |
| 磁盘不足、只读输出目录 | 有恢复指引，无未完成成品文件 | M1 |
| 旋转视频、奇数尺寸、VFR | 方向与画面符合预期，音画同步 | M0/M2 |
| HDR 输入 | 可识别并阻止首版不可靠转换 | M0/M2 |
| 编码器不可用/运行失败 | 可说明问题；受限重试，不陷入循环 | M1 |
| 外站请求、伪造 Host、越界符号链接 | 拒绝未授权访问，不读取根目录外媒体 | M1 |
| 断网、端口冲突、缺 FFmpeg | 离线可处理；启动和依赖错误易恢复 | M2 |

测试采用参数/状态机单元测试和真实 FFmpeg 集成测试组合；模拟错误用于覆盖磁盘和进程故障，但成功编码必须包含真实集成样本。

## 8. 性能与质量基准

以下为测量方案，**尚无实测数据**。

- 样本：1080p 30fps、1080p 60fps、4K 30fps，短片与长片各一；固定源文件哈希。
- 同一输入分别记录软件、硬件输出；每组至少 3 次，记录中位数和范围，说明是否包含探测、暂存和结果验证。
- 记录机器、内存、电源状态、版本、完整参数、源与输出大小、墙钟耗时、处理 fps、Node/FFmpeg 分别的峰值 RSS。
- 记录浏览器交互是否卡顿、失败率和连续运行后的表现；测试条件保持一致并避免并行任务干扰。
- 用灰度参考评估转换结果，检查中性色块与灰阶梯度；不能直接把彩色源与黑白结果的差异当成压缩质量损失。
- 音画同步使用带明确视听标记的夹具验证；无剪辑夹具建议误差不超过 100ms，超出需调查时间戳和编码延迟。
- 大文件测试重点验证内存不会随输入总大小近似线性增长，而不是声称“零内存”或先写死通用占用上限。

本地体验目标：依赖齐备时启动到可交互页面约 5 秒内；取消响应约 3 秒内，强制清理总时限约 10 秒；20 个混合任务不会拖垮 UI。所有数字均为待验证目标，发布时用测量结果替换。

## 9. 后续版本触发条件

| 需求 | 何时启动 |
| --- | --- |
| Windows/Linux 正式支持 | 有平台测试环境和维护者，路径/取消/安装验收通过 |
| 桌面安装包 | 用户试用证明终端安装是主要障碍，且有精力维护签名与更新 |
| HDR 转 SDR | 有代表性样本、明确的色调映射策略和视觉验收能力 |
| 更多黑白风格 | 标准转换稳定，用户明确需要对比度/亮度预设 |
| WASM 在线演示 | 确有免安装试用需求，可独立维护体积和能力限制 |
| 更高并发 | 长时间基准证明吞吐改善且交互和温度可接受 |
