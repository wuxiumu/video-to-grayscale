# 02 · 产品与技术优化方案

## 1. 产品定位

一句话：**一个在本机完成批量黑白视频转换的轻量工具，可先预览、查看进度，并安全导出。**

首批用户：Mac 上经常处理短视频和课程素材、愿意安装 Node.js 与 FFmpeg、但不想记转码命令的人。面向完全不使用终端的人，需要后续桌面安装包，首版不宣传为全民开箱即用。

核心流程：选择素材 → 预览效果 → 确认输出 → 批量转换 → 查看结果。

## 2. 文件导入：必须区分两条路径

### P0 主入口：授权目录内直接读取

拟定启动方式（尚未实现）：

```bash
npm ci
npm start -- --input-dir "$HOME/Movies" --output-dir "$HOME/Movies/Grayscale"
```

- 服务启动后打开带一次性会话引导信息的本地页面。
- 页面内通过文件浏览器选择已授权根目录下的文件，可多选。
- FFmpeg 直接读取原始文件，不生成输入副本。
- 首版通过启动参数确定输入、输出目录；界面显示两者。目录变更先重启服务，原生目录选择器后续再做。
- 输出目录在输入目录内时，从递归扫描中排除，防止把结果重新入队。

### P0 便捷入口：拖拽或浏览器文件选择

- 将文件流发送到本机服务，落入应用暂存目录，完成后才进入探测。
- 界面明确显示“复制到本机临时目录”，具有独立的复制进度和取消入口。
- 禁止整文件 `arrayBuffer()`、Base64，以及后端整文件内存缓存；采用带背压的流式传输。
- 明确会额外占用一份输入空间。大文件提示使用目录入口，但不人为宣称无限文件大小。
- 应用只清理自己创建的暂存文件；待重试任务先保留，删除和清理有明确入口。

这两种方式共用 sourceId；前端不能通过任意路径参数读取系统文件。

## 3. 首页与交互

1. **环境状态**：FFmpeg/ffprobe 是否可用、当前输出目录；缺依赖给可复制步骤。
2. **素材入口**：浏览授权目录、拖拽文件；筛选失败项，去重提示。
3. **设置**：标准黑白；质量优先/速度优先；音频自动/AAC/静音；默认保持分辨率和时间轴。
4. **队列**：文件名、源大小、时长、状态、当前进度、取消/重试。
5. **结果**：输出位置、耗时、输出大小、播放、在文件管理器显示。

P1 加入 FFmpeg 生成的 3–5 秒短片预览及前后切换。原视频浏览器无法解码时，显示缩略图并通过可播放的代理片段比较。CSS 灰度只可作为标注清楚的快速示意，不代表最终导出。

空状态、加载状态、错误恢复、键盘操作和移动窗口下的布局均需设计。批量统计同时展示文件数量与当前任务进度，不把不同长度视频简单平均成精确总百分比。

## 4. 技术架构与范围

建议 Node.js + TypeScript；前端采用 HTML/CSS/TypeScript 与轻量构建工具；后端采用小型 HTTP 框架，进度用 SSE，操作用 HTTP。实施时选择并锁定仍受支持的 Node LTS 与依赖版本，不追随未验证的新版本。

```text
浏览器 UI
  ├─ HTTP：导入、任务操作、预览、结果
  └─ SSE：状态变化与进度
         ↓
Node 本地服务（回环地址、会话鉴权）
  ├─ 受限文件访问 / 流式暂存
  ├─ ffprobe 探测 / 参数生成
  ├─ 串行队列 / 原子任务快照
  └─ FFmpeg 子进程 / 输出校验
         ↓
已授权输入目录 + 输出目录 + 应用数据目录
```

拟定模块结构：

```text
src/
  client/                  # 页面、队列视图、样式
  server/
    files/                 # 根目录校验、暂存、输出命名
    media/                 # 探测、参数构造、进度和结果验证
    jobs/                  # 状态机、持久化、调度、取消
    api/                   # 鉴权、接口和 SSE
  shared/                  # 任务、预设和错误结构
scripts/                   # 环境诊断、基准、测试素材生成
tests/                     # 单元与集成测试
doc/
```

避免一个 `server.js` 同时承担文件操作、路由和所有转码逻辑。首版无需数据库服务；单进程、原子替换的 JSON 快照即可，后续有真实需求再迁移 SQLite。

## 5. 编码契约

以下是项目拟定行为；具体参数须在 M0 使用本机样本验证。

| 项目 | 首版决策 |
| --- | --- |
| 输入范围 | 以 ffprobe 结果为准；优先验证 MP4/MOV/MKV 中的 SDR H.264/H.265，扩展名仅做提示 |
| 输出 | MP4、H.264、yuv420p；不保证体积小于原片，不称无损 |
| 灰度 | `hue=s=0`，保留连续灰阶；不做二值化、不承诺原始灰度平面格式 |
| 质量优先 | 经能力检测可用的 libx264；以 CRF 20、medium 作为待验证起点 |
| 速度优先 | macOS VideoToolbox；目标码率按分辨率/帧率建立预设，不能套用 x264 的 CRF |
| 音频 | 自动模式仅已验证兼容 AAC 时复制，否则转 AAC；无音轨可正常导出，静音为显式选择 |
| 多流 | 选择首个非封面视频和首条音轨；额外视频、音轨、字幕、附件不导出，转换前提示 |
| 分辨率 | 通常保持；奇数尺寸必要时补至偶数并提示，不静默缩小 |
| 旋转 | 正确应用显示方向；输出验证方向，避免像素旋转后又保留重复旋转标记 |
| VFR | 不默认加固定 `-r`；以实际输出时间轴和音画同步为验收依据 |
| HDR | 检测 PQ/HLG/杜比视界相关信息并阻止首版转换；信息不明时提示人工确认来源 |
| 元数据 | 默认不复制位置和用户标签；必要显示/色彩信息按处理后的实际含义写入并验证 |

灰度滤镜依据：[FFmpeg hue 文档](https://ffmpeg.org/ffmpeg-filters.html#hue)。

环境诊断检查可执行文件、版本、编码器列表，再执行短片试编码。列表存在不等于运行可用。对于当前实际任务的编码器故障，允许从头软件重试一次并在 UI 显示；磁盘、权限、损坏输入错误不走此回退。

## 6. 队列、持久化与输出可靠性

```text
importing → probing → queued → running → verifying → completed
                   ↘ failed       ↘ canceling → canceled
queued → canceled
running / verifying（服务异常退出后）→ interrupted
failed / canceled / interrupted → 新 attempt → queued
```

- 暂停队列是调度标志，不是任务状态；当前任务继续完成。
- 服务端保存 jobId、sourceId、预设快照、attempt、状态、时间和错误码。客户端刷新先拉快照，再订阅带递增事件编号的更新；断线后重新对齐状态。
- 任务状态变化立即持久化；高频进度限频保存。异常退出的任务标记 interrupted，用户重试从头开始。
- 使用结构化进度，百分比在处理期间最多显示 99%；只有进程成功且输出验证通过后完成。未知时长显示 elapsed。
- 取消需等待子进程退出；超时终止进程树。退出与取消竞争时，已接受取消的 attempt 不得提交为完成。
- 默认输出 `源名-gray-短任务ID.mp4`；冲突重新分配。临时文件位于同一输出文件系统，例如 `.job-id.partial.mp4`。
- 完成后检查视频流、非零时长、音轨策略及可解码性，再用不会覆盖已有目标的提交方法发布结果；普通 rename 可能覆盖现有目标，不能直接视为安全提交。
- 失败只清理本任务的部分文件。重启核对输出、临时文件和快照；不自动删除未知文件。
- 存储空间预估只是提示，运行时仍需处理 ENOSPC。输出不存在、只读、源被移动均有独立恢复说明。

## 7. 本地服务的必要约束

- 仅监听 `127.0.0.1`；默认不开局域网访问。端口占用时选择空闲端口并打印真实地址。
- 引导令牌从 URL fragment 交换成 HttpOnly、SameSite 会话后立即清除 fragment；媒体、SSE 和所有 API 都验证会话。
- 限制 Host、Origin 和请求方法；不用通配 CORS。跨站写请求拒绝，媒体 GET 即使无 Origin 也必须鉴权。
- 路径使用 `realpath` 加目录边界检查，拒绝 `..`、符号链接越界、任意 URL/播放列表输入。用户只操作已注册 sourceId/jobId。
- 子进程采用 `spawn(binary, args, { shell: false })`；不接受任意 CLI 参数或任意滤镜表达式。设置输入协议范围，避免媒体引用远程资源。
- 预览和导出媒体支持 Range；不能通过任意路径 HTTP 下载本机文件。
- 日志按需导出，默认脱敏用户目录和文件名，不上传遥测。

子进程调用依据：[Node.js child_process 文档](https://nodejs.org/api/child_process.html#child_processspawncommand-args-options)。

## 8. 最小接口契约

| 接口（拟定） | 行为 |
| --- | --- |
| `GET /api/environment` | 能力与依赖诊断 |
| `GET /api/files?directoryId=…` | 已授权目录的子目录及素材 |
| `POST /api/imports` | 流式暂存，返回 sourceId |
| `POST /api/jobs` | sourceId 列表、预设、幂等请求 ID；返回每项校验结果 |
| `GET /api/jobs` | 完整队列快照与事件游标 |
| `GET /api/events` | SSE 更新，断线补快照 |
| `POST /api/jobs/:id/cancel`、`retry` | 明确状态转换；重复取消幂等 |
| `POST /api/queue/pause`、`resume` | 控制后续调度 |
| `GET /api/jobs/:id/output` | 已完成结果的受控媒体访问 |
| `POST /api/jobs/:id/reveal` | 仅打开该任务输出位置 |

预览复用同一转码模块和资源调度，不允许用户不断点击预览绕过串行限制；使用独立临时文件及清理周期。
