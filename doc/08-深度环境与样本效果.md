## 4. 基本需求判断

已检查首帧、中间帧、末帧：

- 身体、手臂、头部及靠近镜头的鞋底具有可辨识的轮廓与远近层次。
- 原片的颜色、皮肤明暗和鞋面纹理不再直接决定深度亮度。
- 更靠近镜头的鞋底和手臂呈亮色，较远背景呈暗色，符合当前近白远黑约定。
- 保留原动作帧序列和播放速率，没有音轨，也没有加文字、水印或拼接画面。

**结论：符合首轮“真实模型生成的无音频相对深度参考视频”的基本交付要求。**

尚未接入目标人物生成模型，因此不能将此结果表述为“动作迁移已验证成功”。手指、反光材质边缘、被遮挡的身体部分，以及快速运动下的时序一致性仍可能存在误差。关键帧目视检查不能替代逐时刻的运动一致性评估。

## 5. 实现与规划的差异

- 本轮采用逐任务 Python 子进程，每个任务加载一次模型；不是常驻并跨整批复用模型。这样便于取消和内存释放，后续再优化冷启动。
- Python 两遍处理：缓存推理尺度的 float32 深度；按镜头采样统计 2%/98% 分位数；统一归一化后编码。
- 镜头切分是简单 RGB 差异启发式，样本检测为一个镜头；复杂剪辑尚未验证。
- 没有对深度做跨帧均值平滑，也没有接入视频深度模型；固定范围只能减少归一化引入的闪烁，不能消除网络漂移。
- 输入先由 FFmpeg 规范旋转并写入无损临时视频；当前限定 CFR、方形像素和长宽比 ≤ 2.5。检测到不满足条件的素材会报错，不静默改变动作时序。
- PyAV 记录的是规范化中间视频的时间戳，Matroska 毫秒时间基会带来不足一帧的舍入误差；新 manifest 字段为 `normalized_input_pts_seconds`。首轮 manifest 早期字段名为 `source_pts_seconds`，同样应按此语义理解。
- 默认无音频；显式 `--audio auto`/`aac` 可用于其他用途，不再是默认控制素材配置。
- 深度模式的 speed 选项只切换 x264 编码预设，不加速模型网络，也不使用 VideoToolbox。

## 6. 使用命令

环境本机已经安装完成，直接使用：

```bash
# 默认深度 + 无音频
npm run convert -- test/2026-09-15_153332_222.mp4

# 更高推理尺寸
npm run convert -- test/2026-09-15_153332_222.mp4 --depth-size 518

# 近黑远白
npm run convert -- test/2026-09-15_153332_222.mp4 --invert-depth

# 普通灰度 + 保留音频
npm run convert -- test/2026-09-15_153332_222.mp4 --mode grayscale --audio auto

# 网页
npm start -- --input-dir ./test
```

新电脑首次执行 `npm ci` 与 `npm run setup:depth`。当前环境与深度模式在本机 macOS 验证，不承诺任意 Python/操作系统组合都已验证。
